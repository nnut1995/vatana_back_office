# Vatana Back Office: design critique (18 Oct 2026)

**Method.** DEGRADED: single-context (the design review and the evidence pass ran in one session, not as two independent reviewers). I ran the app in a sandbox with the seed order and the 63 `[MOCK]` orders, signed in as admin and as a Decor-only staff user, and took screenshots at tablet landscape (1024×768), tablet portrait (768×1024), phone (390×844) and desktop (1440×900). I also tested keyboard focus order and scanned the code. Two gaps come from the sandbox, not the app: product photos could not load (no S3), and the production report failed to load because the test database does not support its query. Neither is scored. Screenshots are in [critique-2026-10-18/](critique-2026-10-18/).

Judged against [PRODUCT.md](../vatana_back_office/PRODUCT.md): the owner and staff use it mostly on tablets, and it has to be easier than paper and Excel.

## Design specificity

**Partly authored.** The production sheet and the Decor work log are clearly built for this factory, with shirt-type pills, the paired kids' size headings, shifts, and ordered-versus-done quantities. Everything around them is the stock Material UI admin template: indigo primary, a permanent left drawer, a row of stat cards and a list of bars. Swap the logo and it could be any back office.

## Overall impression

The data model and the audit trail are solid. The interface has not caught up with the fact that it is used on tablets. At 1024px, the device it is mainly used on, a fixed 232px menu takes a quarter of the width, and the size grid that holds the core numbers breaks. On the order page each number wraps one digit per line ("1 / 1 / 0"). In the department queue the L and XL columns are cut off.

**Biggest opportunity:** make tablet landscape the main layout. Collapse the menu, and give the size grid the full width so every size and quantity is readable without scrolling. Most of the other issues are cheaper once that is done.

## What's working

- **The Decor work dialog.** Worker, step, date and shift are all on one screen, there is one input per colour and size with the ordered and done amounts under it, and "เติมยอดที่เหลือ" fills the remainder. This is the best screen in the app and shows the pattern to use elsewhere.
- **Staff only see their own work.** A Decor-only account sees only the Decor menu and queue, with no admin pages to get lost in.
- **The order page follows the paper sheet.** Style code, design, work details by front, back and sleeve, and colour rows all match what the owner already knows.

## Priority issues

**[P0] The size grid is unreadable at tablet width.** On the order page at 1024px each quantity wraps one digit per line, and in the department queue L and XL are cut off. These are the numbers the whole factory works from, and misreading one means producing the wrong quantity. *Fix:* below the `lg` breakpoint, move the work-details column under the grid and give the grid at least 5 × 56px columns with `white-space: nowrap` and tabular numerals. *Command:* `adapt`. ([screenshot](critique-2026-10-18/order-size-grid-tablet.png), [queue](critique-2026-10-18/decor-queue-tablet.png))

**[P0] The menu is permanent on every screen size.** It is always 232px wide. On a phone the page gets about 150px, so the Decor heading breaks into two lines and the search box is cut off. In tablet portrait the 18-item menu takes 30% of the width. *Fix:* use a temporary drawer with a menu button below `lg`. Collapse the 11-item "แผนก" group by default, and hide it for staff with only one department. *Command:* `adapt`. ([phone](critique-2026-10-18/decor-queue-phone.png))

**[P1] Saves change data with no confirm and no feedback.** The status dropdown on the orders list and order page saves "ยกเลิก" instantly. The new-order dialog closes on a backdrop tap and loses the work. Products without a code or name are dropped silently. There is no Snackbar anywhere, so nothing confirms a save. *Fix:* confirm before cancelling, ask before closing a dialog with unsaved input, show an inline error on the incomplete product, and add one shared "บันทึกแล้ว" toast with Undo for status changes. *Command:* `harden`.

**[P1] Recording work on a SKU is confusing.** "บันทึกการผลิต / เปลี่ยนขั้นตอน" opens with the stage set to the current department, the quantities hidden behind a checkbox, and two notes fields with similar labels. Staff have to work out whether they are logging work or passing it on. *Fix:* split it into two buttons. **ส่งต่อแผนกถัดไป** opens with the next stage already chosen. **บันทึกจำนวน** shows the quantity grid straight away, like the Decor dialog. Keep one notes field. *Command:* `distill`. ([screenshot](critique-2026-10-18/record-dialog-tablet.png))

**[P1] Touch targets are too small, and quantity fields bring up the full keyboard.** There are 52 `size="small"` controls, the main actions on each card are about 30px tall outlined buttons, and no quantity field sets `inputMode="numeric"`. *Fix:* make each card's main action a contained button at least 44px tall, and add `inputMode="numeric"` to every quantity input. *Command:* `adapt`.

## Persona red flags

- **The owner on a tablet (from PRODUCT.md).** The dashboard has 4 count cards and one-colour bars, so "what is late, and where is it stuck?" takes three screens. Delivery date is not a column in the orders list. The status dropdown in every row invites accidental changes while scrolling.
- **A floor worker on a shared tablet (from PRODUCT.md).** After login they get an overview with one card, then a queue where every SKU is a full sheet with 4 outlined buttons of equal weight. "บันทึกงานที่ทำแล้ว" is the action they need most, and it is the smallest thing on the card.
- **Sam, a keyboard or screen-reader user.** It takes 19 Tab presses through the menu to reach "สร้างคำสั่งซื้อ", and there is no skip link. Order rows open only on a mouse click (`onClick` on `TableRow`), so they can't be opened from the keyboard or in a new tab.

## Minor observations

- Thai text is still rendered with Geist plus system fallbacks, because Geist has no Thai glyphs. Thai looks different on each tablet. Load Noto Sans Thai, IBM Plex Sans Thai or Sarabun.
- The shirt-type pill ("เสื้อผู้ใหญ่") is the largest text on every product card, larger than the design name.
- Style codes and references use monospace, which reads as decoration more than data. Tabular numerals in the sans font would do the job.
- The department overview shows 11 cards of the same size, including empty ones ("0 รายการสินค้า"). Sorting by workload, or muting the empty departments, would make it easier to scan.
- The work remark uses a 3px orange left border, which is a pattern the checklist avoids. Use a tinted background with an icon instead.
- `Sidebar.tsx` and `OrderStatusBadge.tsx` are still unused, and the dashboard bars don't use the status colours.
- The production report's error state ("โหลดประวัติการผลิตไม่สำเร็จ") has no retry button.
- The login page still pre-fills `admin@vatana.local` and shows the default password.

## Questions to consider

- Would the owner rather open the app to a "today" view (overdue orders, orders due this week, pieces stuck per department) than to totals?
- Should a staff tablet be signed in to one department all day, so it opens straight to that queue?
- Is the full production sheet needed in the department queue, or would one compact row per SKU, expanded on tap, be enough?
